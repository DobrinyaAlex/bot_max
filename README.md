# MAX Bot v2 — объявления с пре-модерацией

Бот для сбора объявлений и публикации в сеть каналов мессенджера MAX.
Устойчивые сессии в SQLite, канал модерации, лимиты, кэш фото, админ-панель.

## Что изменилось относительно v1

| Было | Стало |
|------|-------|
| `limits.json` + `user_states` в памяти | SQLite: сессии, лимиты, объявления, кэш фото, настройки |
| Рестарт → потеря сессии | Сессия живёт в БД, рестарт контейнера её не рвёт |
| Капча без лимита попыток | 3 попытки → бан 10 минут |
| Нет валидации | Телефон, имя, стоп-слова, длина текста |
| Публикация сразу в канал | Все объявления → **канал модерации** → Approve/Reject |
| Нет предпросмотра | Экран «Опубликовать / Изменить / Отмена» |
| Нет админ-панели | `/admin stats|pending|ban|unban|limits|channels` |
| Нет `/cancel`, `/help` | Добавлены + таймаут сессии 15 минут |
| Нет логов | Файл `bot.log` с ротацией + алерты в канал модерации |
| Нет кэша фото | Кэш `token` по URL + 3 ретрая + лимит 10 МБ |
| Нет «Мои объявления» | `/my` — список, удаление, повтор |

## Переменные окружения (BotHost → Environment)

Обязательные:
- `MAX_BOT_TOKEN` — токен бота.
- `CHANNELS_JSON` — список каналов для публикации (см. ниже).
- `ADMIN_CHAT_ID` — **ID канала/группы «Модерация»** (отрицательное число). Сюда приходят заявки и алерты об ошибках.

Опциональные:
- `ADMIN_USER_ID` — ваш личный user_id в MAX. Нужен только для команд `/admin` в личке и как последний fallback, если канал модерации сломается. Если `/admin` не нужен — можно не задавать.
- `DATA_DIR` — папка данных (по умолчанию `/app/data`).
- `DAILY_AD_LIMIT` — дневной лимит объявлений на пользователя (по умолчанию `6`).

### `CHANNELS_JSON`

```json
[
  {"name": "Недвижимость", "id": -80504470799745},
  {"name": "Услуги",       "id": -80503811966337},
  {"name": "Вакансии",     "id": -80503860135297},
  {"name": "Автозапчасти", "id": -80504153212289},
  {"name": "Авто/Мото",    "id": -80168518583681},
  {"name": "Барахолка",    "id": -80506663765377}
]
```

Бот должен быть администратором во **всех** этих каналах с правом публикации, а также в канале модерации (`ADMIN_CHAT_ID`) — с правом публикации и удаления.

## Как получить ID канала модерации

1. Создайте приватную группу или канал «Модерация MAX».
2. Добавьте бота администратором с правом публикации и удаления.
3. Отправьте в этот чат любое сообщение.
4. Откройте `bot.log` на BotHost — там будет строка:
`msg chat_id=-1001234567890 user_id=...`
Число после `chat_id=` — это `ADMIN_CHAT_ID`.

## Как получить ADMIN_USER_ID (если нужен /admin)

1. Напишите боту в личку `/start` с того аккаунта, который будете использовать как админ.
2. В `bot.log` появится: `start_flow user_id=123456789 chat_id=123456789`
3. Число после `user_id=` — это `ADMIN_USER_ID`.

## Команды бота

Пользователь:

- `/start` — начать оформление
- `/cancel` — отменить текущее действие
- `/help` — справка
- `/my` — мои объявления (удаление, повтор)

Админ (только при заданном `ADMIN_USER_ID`, в личке бота):

- `/admin` — справка
- `/admin stats` — статистика
- `/admin pending` — заявки на модерации
- `/admin ban <uid> [минут]` — бан
- `/admin unban <uid>` — разбан
- `/admin limits <uid>` — лимиты пользователя
- `/admin channels` — список каналов

## Как работает модерация

1. Пользователь заполняет объявление и выбирает канал.
2. Заявка уходит в **канал модерации** с кнопками «Одобрить / Спам / Лексика / Контакты / Другое».
3. Кнопки нажимает любой администратор канала модерации — но обработка кнопки записывается в БД, кто бы ни нажал.
4. При «Одобрить» бот публикует пост в целевой канал и уведомляет автора.
5. При «Отклонить» — автору приходит причина, в канал ничего не уходит.

Приоритет адресов для заявок (`moderation_target()`):
`ADMIN_CHAT_ID` (канал модерации) → сохранённая личка админа из `/start` → `ADMIN_USER_ID` → всё сломано, заявка теряется.

## Известные ограничения

- **Удаление опубликованного объявления** зависит от поддержки метода `bot.delete_message` в `maxgram`. Если метод отсутствует, кнопка «Удалить» вернёт понятную ошибку вместо падения.
- `ssl=False` оставлен намеренно — BotHost не принимает сертификаты Минцифры. Токен идёт по HTTPS, но проверка сертификата отключена. Бот ходит только на `platform-api2.max.ru`.
- Rate-limit хранится в памяти процесса — при рестарте сбрасывается. Сессии, лимиты, объявления — в БД, не сбрасываются.
- `bot.db` — обычный SQLite-файл. Если BotHost пересоздаёт контейнер при деплое, `/app/data` может не сохраниться. Проверьте персистентность папки после первого деплоя.

## Миграция с v1

Файл `limits.json` больше не читается. При первом старте v2 лимиты обнулятся.
Старые пользователи при следующем `/start` просто получат новую сессию — ничего не сломается.

## Проверка после деплоя

1. В логе должно появиться:

```
=== БОТ ЗАПУЩЕН ===
Каналы: ['Недвижимость', 'Услуги', ...]
ADMIN_USER_ID=... ADMIN_CHAT_ID=...
```
2. С другого аккаунта оформите тестовое объявление до выбора канала.
3. Заявка должна прийти **в канал модерации**, не в личку.
4. Нажмите «Одобрить» — пост уйдёт в целевой канал.
5. Отправьте боту в личку `/admin stats` (если `ADMIN_USER_ID` задан) — должен быть ответ.
